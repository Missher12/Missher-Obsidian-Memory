# `.memory` 是什么

这是插件的**协议目录**，不是笔记内容。目录名以点开头，Obsidian 默认不把它
登记进笔记索引，所以它不会出现在你的笔记列表里。

```
requests/  外部（CLI / MCP / 其他工具）排队进来的写请求，一个请求一个文件
receipts/  每个请求的处理结果：completed / conflict / failed / expired
probe.json 插件启动时的探测标记（判断隐藏目录是否可读）
```

## 两条必须分清的语义

- **accepted（已排队）**：请求已经**持久**写进 `requests/`。这不代表内容已经进库。
- **completed（已提交）**：`receipts/` 里出现了对应回执，才算真的写进 Markdown。

请求文件的生命周期：

- 处理**成功**并写下有效回执（`completed` / `conflict`）之后，对应的请求文件会被**删除**；
- 处理**失败或过期**（`failed` / `expired`）的请求会**留在原处**，方便排查后重新提交。

因此：

- 看到 `requests/` 里还有文件 → 要么还没被处理（插件没开），要么处理失败了；
- 看到 `receipts/` 里有 `conflict` → 内容和排队时读到的不一样（多半是人工编辑过），
  **本次写入被取消了**，你的编辑完好无损。

## 目录里的东西不是都可以一删了事

`.memory/` **不是一个纯粹的缓存**，里面至少有三类有状态的东西：

1. **请求正文**。`requests/` 里的文件带着这次要写的内容。还没处理的请求，
   删掉就等于放弃这次写入——正文只在这里，别处没有副本。
2. **删除 / 遗忘账本**。一条记忆被删除后，`receipts/` 里的历史回执是
   「它曾经存在、什么时候被谁删掉」的唯一记录。
3. **待审补丁**。AI 提议但用户还没接受的修改存在这里。
   删掉等于把待审内容一起丢掉。

所以：

- `receipts/` 下的历史回执可以清理，但清理之后**就再也查不到**上面那两件事；
- 整个 `.memory/` 目录**不要随手删除**。真要清空，先确认：
  `requests/` 里没有你还想写的请求、没有待审补丁、也不在乎删除账本。

## 不要手工编辑

**不要手工编辑 `requests/` 里的文件。** 那些文件带指纹与期望哈希，
手改会让插件拒绝处理，而你可能以为「只是改了个错字」。

回执同样是**记录**，不是配置：改它不会改变已经发生的写入，
只会让「这次写没写成功」变得无法判断。
