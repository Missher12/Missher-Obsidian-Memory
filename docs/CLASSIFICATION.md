# Missher 中文分类（0.2.0）

目录决定放在哪里；确认状态决定是否成为事实；作用域决定何时可以调用。三者独立。

## 设置

1. 在插件设置中选择“Missher 中文分类”。旧设置默认沿用原数字分类。
2. 选择“记忆根目录内”，文件写入根下的中文分类；或选择“Vault 现有分类文件夹”，绑定 Vault 内同级目录。
3. 新库推荐记忆根为 `记忆库`、位置为 Vault 现有分类。点击“预览并应用”，核对实际目录，确认后重载。
4. 如需沿用不同名字，可展开“自定义分类文件夹”，为每类填写相对目录。

配置仅作用于明确绑定的目录和原记忆根，普通旧笔记仍可在 Obsidian 直接浏览，但不会被自动提取或改写。根目录之外的旧记忆不会因改配置而自动搬迁。已采用 Vault 分类的库不能在此入口更换状态根；新旧扫描目录重叠的换根也会拒绝，以免同一批笔记脱离原来的遗忘记录和队列。

索引、待审补丁、删除记录和队列仍保存在 `<记忆根>/.memory/`。这些状态应与托管笔记一起备份；不能只移动 Markdown 或只复制新配置。

## 分类表

| 文件夹 | 分类标识 | 用途 |
| --- | --- | --- |
| 记忆库 | memory | 具体事实、偏好、约定；未明确分类的内容 |
| 用户画像 | profile | 稳定特点与目标概览，引用原始记忆 |
| 场景 | scene | 某种任务下需要的约束、资料与流程入口 |
| 知识库 | knowledge | 可复用的概念、原理与已整理知识 |
| 调研 | research | 来源、比较、待查证问题 |
| 决策 | decision | 选择、原因、日期与适用范围 |
| 规划 | planning | 目标、路线图与下一步 |
| 工作流 | workflow | 可重复执行的步骤和验收条件 |
| 教训 | lesson | 问题、原因、改进与复测结果 |
| 日记 | journal | 当日事件与过程 |
| 周报 | weekly | 周期进展、问题与后续安排 |
| 月报 | monthly | 阶段趋势与目标调整 |
| 系统 | system | 工具、环境、配置和维护说明 |
| 模板 | template | 内容结构；不作为事实进入检索、画像或 MCP 召回 |

快速记住窗口可选类别、填写短标题。没有显式类别时，knowledge、decision、project、event 分别对应知识库、决策、规划、日记；其余进入记忆库。AI 提议始终待确认，放入知识库或工作流不会自动提升可信度。

每份内容保留一个权威条目。画像、场景、周报和工作流用双链引用来源，不为每个分类复制同一事实。这是整理规范；本版不会自动改写现有导航页、拆分画像或移动旧笔记。

## 文件命名

新建托管笔记采用短标题，如 `沟通偏好.md`、`发布前检查.md`，稳定 ID 保存在元数据中。同名文件已存在则使用 `-2`、`-3` 等后缀，原笔记不覆盖。没有填写标题时从内容生成。

日记建议填写 `YYYY-MM-DD`，周报建议 `YYYY-Www`（ISO 周次），月报建议 `YYYY-MM`，决策建议 `YYYY-MM-DD-主题`。这些是填写标题的规范，本版不从正文猜测事件日期，也不替换原来的日记插件或周期笔记。

## CLI / MCP

外部程序的根、布局、位置和目录映射必须与插件设置一致。布局是启动配置，模型工具参数只允许选分类，不能更改目录范围。

```bash
node packages/cli/dist/cli.js remember --vault /path/to/Vault \
  --root 记忆库 --layout missher --placement vault \
  --category knowledge --title 检索约定 --text "检索结果应保留来源。" --json

node packages/cli/dist/mcp.js --vault /path/to/Vault \
  --root 记忆库 --layout missher --placement vault
```

自定义目录时两个入口都加 `--folders-json '{"knowledge":"资料/知识"}'`。
也支持启动环境变量 `MOM_ROOT`、`MOM_LAYOUT`、`MOM_PLACEMENT`、`MOM_FOLDERS_JSON`。
MCP 的 `memory_remember` 提供 `category` 和可选 `title`；AI 生成提议仍走现有待确认规则。
外部写入仍需等待 Obsidian 提交，`accepted` 只代表排队，`completed` 才代表文件提交。

## 复盘与独立使用

无需模型或 MSE，也能记录、管理、检索和运行本地确定性检查。配置模型后才有语义提取、问答和 AI 复盘；自动生成内容保持待确认。

建议使用“日记 → 教训 → 工作流”的整理顺序：先留事件证据，再写原因与改进，复测后形成可执行方法。不会仅因复盘时间到了就自动认定方法已验证。MSE 可选互动的当前能力和下一步见 [协议方向](MSE-INTERACTION.md)。
